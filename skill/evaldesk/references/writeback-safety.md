# Write-back Safety

Read this reference before running `evaldesk commit --apply`.

## Approval Gate

Run `evaldesk commit --session '<directory>'` first. It validates local results
and creates `commit-preview.json` without changing Feishu.

Before applying, show the user:

- source sheet and revision;
- affected physical rows and cell count;
- each target column and field type;
- before and after values.

An earlier request to build, test, or demonstrate EvalDesk is not approval to
write.

## Validation Gate

Reject the write when:

- the template is unsupported;
- a result contains an unknown physical row;
- a field or column is outside the manifest allowlist;
- a score or label is outside the captured validation options;
- MOS is non-numeric or outside 1 through 5;
- a reason exceeds the supported length;
- the current Feishu revision differs from the prepared revision.

Never bypass revision conflicts. Prepare a fresh session and reconcile them.

## Write Semantics

- Write only values that differ from the source snapshot.
- Keep machine scores, historical rounds, other models, and expert fields
  read-only.
- Send multi-select labels as multiple values, not a comma-joined scalar.
- Keep unrelated values, formulas, styles, merges, dimensions, and metadata
  unchanged.
- Use the validated batch write generated by EvalDesk.

## Verification

After writing, read every affected range and compare every intended value.
Report a verification failure even when the write API returned success. Do not
automatically retry a partial or mismatched write.
